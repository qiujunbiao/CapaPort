# CapaPort 桌面端 UI 系统升级设计

## 1. 背景与目标

CapaPort 桌面端已经形成黑、米白、橙色的品牌识别与稳定的信息架构，但当前表单、选择器、卡片、通知和模态框由页面分别定义，导致控件尺寸、边框、间距、反馈状态和浮层行为不一致。macOS 原生选择菜单还会覆盖品牌视觉，使界面显得生硬且缺乏整体性。

本次升级保留左侧导航、顶部组织栏、内容区和底部状态栏，不改变业务流程，通过统一设计令牌、共享 UI 组件和完整页面迁移，把桌面端升级为精致、现代、克制的专业工具界面。

成功标准：

- 登录、注册、组织引导、工作台、能力库、创作、项目、发布、设置、通知和模态框使用同一套视觉语言。
- 表单控件高度、标签层级、帮助文字、错误状态、只读状态和禁用状态一致。
- 组织、空间及其他选择器不再使用 macOS 原生展开菜单。
- 保留适中紧凑的信息密度，提升可读性，但不降低桌面工具的同屏信息量。
- 不改变现有导航结构、领域数据、接口合同和权限语义。

## 2. 设计方向

视觉方向定义为“现代工业编辑部”：以深色应用框架承载温暖米白内容面，使用克制的橙色强调操作与焦点，辅以清晰的排版、细边框、轻微层级差和有限阴影。

### 2.1 色彩

- 深色框架用于侧栏、顶部栏和底部状态栏，避免扩散到大面积业务内容。
- 米白为主内容背景，面板和表单表面通过轻微明度差建立层级。
- 橙色仅用于主按钮、当前导航、焦点、关键操作和少量品牌标识。
- 绿色、黄色、红色只表达成功、警告和错误，不参与装饰。
- 所有文本和状态组合满足 WCAG AA 对比度要求。

### 2.2 尺寸与密度

- 标准输入、选择器和按钮高度为 42px。
- 紧凑型图标按钮为 34px；长文本输入允许按内容增高。
- 基础圆角为 7px，小型状态标签为 5px，模态框和浮层为 10px。
- 页面间距以 4px 基线递进，主要使用 8、12、16、20、24 和 32px。
- 页面保持适中紧凑密度；窄窗口自动转为单列，不压缩字段到不可读宽度。

### 2.3 层级与动效

- 常规面板主要依靠背景和边框分层，不使用大面积投影。
- 阴影仅用于下拉菜单、通知浮层、模态框和需要脱离页面层级的元素。
- 交互动效为 120–180ms，使用统一缓动，仅覆盖 Hover、Focus、展开、关闭和状态切换。
- 尊重 `prefers-reduced-motion`，不把动效作为理解状态的唯一方式。

## 3. 共享组件架构

共享组件成为桌面端视觉与交互的唯一入口，页面不再直接为通用表单控件和浮层定义专属样式。

### 3.1 基础组件

- `Button`：primary、secondary、quiet、danger 四种语义，统一 loading、disabled 和图标布局。
- `IconButton`：用于关闭、通知、复制、折叠等无文字操作，必须提供可访问名称。
- `Status`：neutral、success、warning、danger 四种状态。
- `Panel`：default、subtle、elevated 三种层级。
- `PageHeader` 与 `SectionHeader`：统一页面标题、说明、状态和操作区。

### 3.2 表单组件

- `Field`：统一标签、必填标识、帮助文字、错误文字和控件关联。
- `Input`：支持前后图标、只读、复制、错误和禁用状态。
- `Textarea`：支持常规内容和等宽代码编辑两种模式。
- `Select`：自定义可访问选择器，替代原生展开菜单。
- `Checkbox` 与 `Radio`：使用品牌化外观，保留原生输入语义。
- `FormSection`：组织相关字段，提供标题、说明和一致间距。

### 3.3 反馈与浮层组件

- `ErrorNotice`、`SuccessNotice`：分别处理页面级错误和成功反馈。
- `EmptyState`：统一空数据、无搜索结果和无权限状态。
- `Popover`：提供定位、边缘避让、焦点管理和点击外部关闭。
- `Dropdown`：在 `Popover` 上提供菜单语义和键盘导航。
- `Modal`：标题与底部操作区固定，中间内容独立滚动。

## 4. 表单与选择器规范

### 4.1 字段结构

字段采用标签、控件、帮助或错误文字的垂直结构。标签为 12px 半粗体；帮助文字使用弱化颜色；错误文字紧邻字段显示。页面级错误保留在页面或表单顶部，但不能代替字段级反馈。

Hover 只轻微加强边框；Focus 使用橙色描边和柔和外环；错误状态使用红色边框与文字；只读状态使用弱化背景并在适用时提供复制操作；禁用状态保持文字可读，不使用过低整体透明度。

小字段可双列排列，描述、Skill、Prompt、项目上下文等长内容独占整行。表单容器宽度和字段最小宽度统一，避免标签与控件错位。

### 4.2 自定义 Select

`Select` 的关闭状态与 `Input` 等高、等边框、等圆角。弹层通过 Portal 挂载到应用浮层根节点，自动选择向上或向下展开，并限制最大高度、内部滚动和窗口边缘距离。

交互要求：

- 支持 Arrow Up、Arrow Down、Home、End、Enter、Escape、Tab。
- 打开时聚焦当前选项；选择后把焦点返回触发器。
- 支持点击外部关闭，且不吞掉触发目标的正常操作。
- 当前项显示勾选标记，键盘焦点和鼠标 Hover 使用不同状态。
- 组织、空间等长列表显示搜索框；短枚举不显示搜索框。
- 空搜索结果、加载、错误和禁用选项具备独立状态。
- 顶部组织选择器使用深色主题，其余选择器使用浅色主题。
- 屏幕阅读器能够获知标签、展开状态、当前值、选项数量和选择结果。

## 5. 页面设计

### 5.1 登录、注册与账号恢复

保留左右分栏构图。左侧维持品牌叙事，降低无关装饰对表单的干扰；右侧表单限制舒适阅读宽度。登录、注册、验证码和账号恢复共用字段组件，错误就地展示，主要操作保持单一明确。

### 5.2 组织引导

创建组织和接受邀请使用精致的分段控件。卡片缩小到合适内容宽度，避免大面积空白。组织名称、邀请令牌和说明文字使用统一字段结构，不再临时生成或要求用户填写不可见的内部标识。

### 5.3 应用框架与工作台

保留左侧导航、顶部组织栏和底部状态栏。侧栏当前项使用窄橙色标记和轻微背景差；顶部组织选择器使用深色 `Select`；通知与头像保持紧凑。工作台指标、Agent 状态和待办通过背景层级、分组和留白组织，减少粗重边框。

### 5.4 能力库、项目与发布

三类列表页面共用筛选栏、搜索字段、状态标签、数据行和空状态。列表行通过间距与分隔线表达层级，操作按钮保持固定位置。项目绑定、同步范围和发布状态使用一致的状态与反馈组件。

### 5.5 创作

保留主编辑区和发布侧栏结构。元数据拆分为清晰的 `FormSection`；Skill、Prompt 和项目上下文编辑器使用等宽内容区、稳定工具栏和明确删除操作。发布侧栏固定在内容视口内，显示目标空间、版本、验证结果和主要操作，不与主表单争夺视觉焦点。

### 5.6 设置

账号、组织、同步、安全和更新按设置分组呈现。组织名称可编辑；slug 与组织 ID 使用只读复制字段；加入组织明确使用邀请令牌。按钮与说明文字位置固定，成功和错误反馈不造成布局跳动。

### 5.7 通知与模态框

通知浮层锚定铃铛按钮，使用箭头指向触发器，显示未读标记、时间、操作和空状态。模态框固定标题与底部操作区，仅中间内容滚动；宽模态框在窄窗口降级为全宽安全边距布局。

## 6. 状态与数据流

共享组件不持有业务数据，只接收受控值、状态和回调。页面继续负责查询、提交和权限判断；组件只负责展示、输入与可访问交互。

异步表单流程统一为：用户提交 → 按钮进入 loading 并防止重复提交 → 页面执行现有请求 → 成功时显示成功反馈或导航 → 失败时映射到字段错误或页面错误 → `finally` 恢复交互状态。

`Select` 的搜索默认只过滤已加载选项；需要服务端搜索的场景通过显式 `onSearch` 和 loading 状态接入，不在组件内部隐式发请求。浮层状态由调用方受控，定位、焦点与关闭行为由共享组件负责。

## 7. 错误、空状态与可访问性

- 认证失效返回登录页；组织接口错误不能显示组织引导页。
- 网络失败、离线、权限不足、空数据和无搜索结果使用不同反馈文案与视觉状态。
- 错误提示使用 `role="alert"`，异步成功状态使用非打断式状态区域。
- 所有字段通过 `label`、`aria-describedby` 和 `aria-invalid` 建立关联。
- 自定义选择器遵循组合框与列表框语义，不以自绘外观牺牲键盘操作。
- 颜色不作为状态的唯一表达，状态同时包含文本或图标。

## 8. 响应式与滚动

应用外壳保持固定，只有中间工作区滚动；模态框只滚动内容区；下拉菜单和通知浮层拥有独立且受限的内部滚动。页面禁止横向滚动，宽表格在设计上优先重排或隐藏次要列。

在窄窗口下，双列表单与设置网格转为单列，创作侧栏回到主内容下方，页面操作区允许换行。侧栏折叠行为保持不变。

## 9. 迁移边界

本次覆盖整个桌面客户端，不同步重做 Web 管理端。允许为桌面端建立共享组件与令牌，但不改变 API、数据模型、权限策略、导航信息架构和业务流程。

迁移按共享基础、认证与组织、应用框架、业务页面、模态与反馈的顺序完成。旧页面样式只在对应页面迁移后删除，避免一次性全局覆盖造成不可控回归。

## 10. 验证策略

自动化验证包括：

- 设计令牌与布局契约测试。
- `Field` 的标签、帮助文字和错误关联测试。
- `Select` 的打开、搜索、选择、键盘导航、Escape、外部关闭和焦点恢复测试。
- `Popover` 的边缘避让与滚动容器定位测试。
- 登录、组织引导、通知、创作、设置和模态框关键交互测试。
- 保持现有桌面端单元测试、端到端流程、类型检查和生产构建全部通过。

视觉验证为登录、注册、组织引导、工作台、能力库、创作、项目、发布、设置、通知和主要模态框生成固定视口截图，检查控件尺寸、文本截断、浮层位置、滚动边界、窄窗口布局和品牌一致性。

## 11. 验收标准

- 全部页面不再直接依赖 macOS 原生展开菜单。
- 同类字段在不同页面具有相同高度、边框、标签、反馈和键盘行为。
- 通知、下拉菜单和模态框不会超出窗口或被滚动容器裁切。
- 页面仅中间工作区滚动，操作区和应用框架保持稳定。
- 登录、组织引导和认证错误路由语义保持正确。
- 所有既有测试与新增组件测试通过，生产构建成功。
- 关键页面截图在标准与窄窗口下均无重叠、截断、抖动或横向滚动。
