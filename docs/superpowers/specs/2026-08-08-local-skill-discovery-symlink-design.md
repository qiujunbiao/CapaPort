# CapaPort 本地全局技能与符号链接发现设计

## 状态

已确认，待实施。

## 背景

桌面端当前把 Codex 用户级目录固定为 `~/.agents`，只读取 `skills` 下第一层目录，并直接跳过符号链接。因此它无法发现 `~/.codex/skills` 中的全局技能、嵌套技能、插件技能，以及通过符号链接安装的技能集合。

本机现状验证了该缺口：`~/.agents/skills` 只有少量直接目录，而大量全局技能位于 `~/.codex/skills`；`context-engineering`、`superpowers` 等技能集合通过符号链接接入，也被当前实现整体忽略。

## 目标

1. 发现 Codex 全局、共享、插件和项目级技能，不再只扫描 `~/.agents/skills` 第一层。
2. 允许扫描所有从可信技能根目录进入的符号链接目标，包括指向用户目录之外的位置。
3. 只把包含 `SKILL.md` 的目录识别为能力目录。
4. 对真实路径去重，避免同一技能从多个入口重复展示。
5. 断链、循环链接和单个无效技能不得导致整个本地发现失败。
6. 能力目录内部的符号链接不得越过规范化后的能力包根目录。

## 非目标

- 不扫描整块磁盘或任意用户选择之外的目录。
- 不把没有 `SKILL.md` 的普通文件夹识别为 Skill。
- 不读取能力包根目录之外的引用文件。
- 不改变 Prompt、Context 和项目上下文的现有发现规则。
- 不在本次调整中修改能力发布、审核或安装协议。

## 可信技能根目录

Codex 发现器使用多根目录模型。默认可信入口包括：

- `~/.agents/skills`
- `~/.codex/skills`
- `~/.codex/plugins/cache` 下已安装插件包中明确命名为 `skills` 的目录
- 已绑定项目的 `.agents/skills`

其他 Agent 继续使用各自既有可信目录。可信意味着允许从该入口开始枚举目录和解析入口符号链接，不意味着允许能力包内部任意越界读取。

不存在的根目录直接忽略。相同根目录经规范化后只保留一次。

## 发现模型

发现过程分为根目录枚举、候选目录解析和能力清点三层：

1. 枚举所有存在的可信技能根目录。
2. 在可信根目录内递归寻找名为 `SKILL.md` 的常规文件。
3. 遇到目录符号链接时解析其规范化目标，并从目标继续寻找 `SKILL.md`。
4. 将 `SKILL.md` 的父目录作为能力包根目录。
5. 使用能力包根目录的规范化真实路径作为稳定去重键。
6. 读取能力元数据并生成现有 `LocalCapabilitySummary`，不改变前端导入流程。

递归发现不依赖固定层级，因此同时支持：

- `~/.codex/skills/release/SKILL.md`
- `~/.codex/skills/.system/imagegen/SKILL.md`
- `~/.agents/skills/superpowers -> /shared/superpowers/skills/...`
- 插件包内部的 `skills/<skill-name>/SKILL.md`

## 符号链接安全边界

允许的入口链接必须由可信技能根目录的遍历直接遇到。入口链接可以指向用户目录之外，例如外接磁盘或 `/opt/shared-skills`。

解析规则：

- 先对链接目标执行规范化，再开始读取。
- 断链跳过并记录 `broken-symlink`。
- 解析过程中重复访问同一目录视为循环，跳过并记录 `symlink-cycle`。
- 同一规范化目标被多个链接引用时只扫描一次。
- 权限不足的目标跳过并记录 `permission-denied`，不终止其他根目录。

能力包根目录一旦由 `SKILL.md` 确定，后续摘要、扫描和导出只能读取该规范化根目录内的常规文件。能力包内部的文件或目录链接如果解析到包根之外，拒绝该链接内容并记录 `package-symlink-escape`。这样既允许链接形式的能力包入口，又不允许能力包借内部链接读取其他本地文件。

## 路径授权模型

当前运行时的 `PathPolicy` 只包含预先声明的 Agent 根目录。新实现需要把经过可信入口验证的符号链接目标作为只读发现根动态加入本次发现上下文。

动态根只授权以下操作：

- 检查 `SKILL.md` 是否存在。
- 计算能力包内常规文件摘要。
- 对用户明确选择的能力执行本地安全扫描和导出。

动态根不会自动成为安装写入目标，也不会扩大项目上下文、卸载或冲突解决的写权限。安装目标仍由原有 Agent 根目录和事务策略决定。

## 去重与来源信息

发现项以规范化能力包路径为第一去重键；如果多个入口解析到同一真实目录，只展示一次。保留所有来源标签用于解释发现路径：

- `global`：全局 Codex 技能目录
- `shared`：共享 `.agents` 技能目录
- `plugin`：已安装插件提供的技能
- `symlink`：通过符号链接进入
- `workspace`：项目级技能

前端继续使用现有能力摘要结构；来源信息通过 Agent 描述或新增的可选来源字段传递，旧数据缺少该字段时仍可正常显示。

## 错误处理

本地发现采用逐根目录、逐候选隔离：

- 单个根目录失败不影响其他根目录。
- 单个 Skill 清单无效时跳过该 Skill。
- 断链、循环、权限不足和内部越界作为可诊断的跳过原因汇总。
- 只有所有可信根目录都无法访问时才显示整体发现失败。
- 界面显示发现数量，并允许展开查看被跳过条目的原因，不暴露目标目录内的文件内容。

## 测试设计

### 路径与发现单元测试

- 发现 `~/.agents/skills/<slug>/SKILL.md`。
- 发现 `~/.codex/skills/<slug>/SKILL.md`。
- 发现多层嵌套的 `.system/<slug>/SKILL.md`。
- 发现插件 `skills` 目录中的 Skill。
- 发现指向用户目录内目标的目录链接。
- 发现指向用户目录外目标的目录链接。
- 多个链接指向同一真实目录时只返回一个能力。
- 断链被跳过且其他能力仍然返回。
- 循环链接被跳过且扫描能够结束。
- 能力包内部越界链接被拒绝。
- 能力包内部指向包内常规文件或目录的链接允许读取，并继续应用去重与循环检测；解析到包外的链接必须拒绝。

### 运行时集成测试

- `detectAgents` 返回 `.agents` 与 `.codex` 的有效 Codex 根。
- `inventoryAgent` 聚合多根目录结果，并保留来源信息。
- 用户选择符号链接能力后，安全扫描和导出可读取规范化包根内的内容。
- 伪造未由可信入口发现的外部根路径仍返回 `PathNotAllowed`。
- 符号链接能力不能被误用为安装写入根。

### 桌面端回归

- 本地发现数量包含直接、嵌套、插件与链接技能。
- 重复来源不产生重复卡片。
- 无效链接只显示跳过原因，不出现“本地发现失败”。
- 选择有效链接技能后可继续执行安全检查和导入流程。

## 验收标准

1. `~/.agents/skills` 与 `~/.codex/skills` 中所有包含 `SKILL.md` 的有效能力均可发现。
2. 可信技能根目录中的符号链接目标无论位于用户目录内外均可发现。
3. 嵌套技能和插件技能可以发现。
4. 同一真实技能目录不会重复显示。
5. 断链、循环链接、权限错误和无效清单不会中断整体发现。
6. 能力包内部链接无法读取规范化包根之外的内容。
7. 未经可信入口引入的任意外部路径仍被拒绝。
