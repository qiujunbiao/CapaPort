# CapaPort 桌面端与 Web 端统一单行表单控件设计

## 状态

已确认，待实施。

## 背景

桌面端与 Web 端目前同时存在多套单行控件尺寸：两端标准按钮的最小高度均为 38px，但部分输入框、搜索框和原生 `select` 分别使用 40px 或 44px。相邻控件因此无法对齐，禁用状态下的按钮也会显得比输入框更矮。

原生 `select` 的弹出层由操作系统绘制。在 macOS 桌面应用中无法稳定控制最大高度、滚动范围和系统选中颜色。本次接受这一平台限制，不为控制弹层高度而改造为自研选择器；只统一原生选择器关闭状态的尺寸和可控样式。

## 目标

1. 按钮高度作为唯一基准，桌面端和 Web 端所有 `Button`、单行 `Input`、`Dropdown`、日期/时间控件和搜索控件共用同一个 `--control-height`。
2. 两端继续使用原生 `select`，统一其关闭状态的高度、边框、字体、背景和禁用态。
3. 保持现有黑／米白／橙色品牌，视觉更精致、现代、克制。
4. 保留原生选择器的键盘操作、焦点反馈和语义化无障碍能力。

## 非目标

- `Textarea`、Markdown 编辑器、代码编辑器及其他多行编辑器单独处理，不接入单行控件高度变量，也不强制为 44px。
- 图标按钮单独处理，不接入单行控件高度变量，也不强制为 44px。
- 不把复选框、单选框、开关和文本按钮强制拉伸到标准单行控件高度。
- 不改变现有表单字段含义、接口参数、权限规则或业务校验。
- 不在本次调整中重构页面布局或品牌色体系。
- 不自研 Dropdown 弹层，不把原生弹层最大高度、展开方向和系统高亮颜色列入本次验收。

## 统一尺寸体系

桌面端与 Web 端分别在应用根样式中声明同名设计变量：

```css
--control-height: 38px;
```

下列标准控件必须直接读取该变量，不再在页面级样式中单独写 40px、44px 等高度，也不允许通过另一套尺寸变量间接产生不同高度：

- `Button`：标准主按钮、次按钮和危险按钮
- `Input`：单行文本、密码、邮箱、手机号和数字输入框
- `Dropdown` 触发器
- 日期与时间控件：`date`、`time`、`datetime-local` 及项目内封装的单行日期选择器
- 搜索控件：原生 `search` 输入和项目内封装的单行搜索框
- 与输入框同行的操作按钮

上述控件统一使用固定 `height: var(--control-height)` 与一致的 `box-sizing: border-box`。边框、内边距、图标、清除按钮和加载态不得改变外框几何高度。禁用状态只能改变颜色与透明度，不得改变高度、边框占位、内边距或外边距。控件组使用交叉轴拉伸或统一高度，不依靠局部像素补偿。

## Dropdown 实现约束

桌面端与 Web 端继续使用语义化原生 `select`、`option` 和 `optgroup`。关闭状态直接读取 `--control-height`，并统一可控的边框、圆角、字体、背景、左右内边距和焦点样式。

原生弹层的最大高度、展开方向、选项悬停颜色和系统选中高亮由运行平台决定。实现中不得通过 Portal、模拟列表或隐藏原生选择器来绕过系统行为。

受控值、禁用项、分组、键盘选择和表单语义继续使用浏览器原生能力，不改变现有事件数据和业务逻辑。

## 迁移范围

扫描桌面端与 Web 端的组织切换、空间与策略、成员管理、组织设置、安全中心、审计筛选、本地发现、能力创作、能力库和市场页面。保留原生 `select` 及现有 `event.currentTarget.value` 逻辑，同时扫描两端全部单行 `input`、日期/时间控件、搜索控件和标准按钮，移除页面级高度分叉。

## 样式收敛

两端删除页面级对标准单行控件的高度覆盖，统一由基础样式负责：

- `Button`、单行 `Input`、`Dropdown`、日期/时间控件和搜索控件全部通过 `--control-height` 获得 38px 高度。
- 相同的边框宽度、圆角、字体行高和左右内边距。
- 输入框、Dropdown 和按钮在同一行时基线与外框完全对齐。
- 禁用状态只改变颜色与透明度，不改变高度、边框占位、内边距或外边距。
- `Textarea`、图标按钮和多行编辑器使用各自的尺寸规则，不强制为 44px。
- 小屏下允许控件组换行，但单个控件仍保持 38px 高度。

## 验证与验收

### 组件测试

- 受控值正确显示和更新。
- 原生分组、禁用项和未知值正确处理。
- 保留原生键盘选择、焦点和表单行为。
- Dropdown 关闭状态读取 `--control-height`，禁用态不改变几何尺寸。

### 布局测试

- 桌面端与 Web 端分别断言 `Button`、单行 `Input`、`Dropdown`、日期/时间控件和搜索控件的计算高度均为 `var(--control-height)` 当前对应的 38px。
- 断言加载态和错误态不会改变控件高度；禁用态只改变颜色与透明度，不改变任何几何尺寸。
- 使用代表性表单验证同行输入框、Dropdown 与按钮上下边缘完全对齐。

### 回归检查

- 扫描标准单行控件是否存在绕过 `--control-height` 的页面级固定高度。
- 运行类型检查、Lint、组件测试、相关端到端测试和生产构建。
- 桌面端重点回归组织设置、空间与策略、审计日志和能力安装流程。
- Web 端重点回归组织管理、安全策略、市场与组织切换流程。

## 验收标准

1. 两端所有 `Button`、单行 `Input`、`Dropdown`、日期/时间控件和搜索控件均由同一个 `--control-height` 驱动，视觉及计算高度一致，当前均为 38px。
2. 两端 Dropdown 保留原生实现，关闭状态的可控样式保持一致。
3. 原生弹层最大高度、展开方向和系统高亮不作为缺陷或验收阻断项。
4. 原生鼠标、键盘和屏幕阅读器操作路径完整。
5. 页面无新增横向溢出、滚动抖动或业务行为回归。
