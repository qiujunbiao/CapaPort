# CapaPort 桌面端与 Web 端统一单行表单控件设计

## 状态

已确认，待实施。

## 背景

桌面端与 Web 端目前同时存在多套单行控件尺寸：两端标准按钮的最小高度均为 38px，但部分输入框、搜索框和原生 `select` 分别使用 40px 或 44px。相邻控件因此无法对齐，禁用状态下的按钮也会显得比输入框更矮。

原生 `select` 的弹出层由操作系统绘制。在 macOS 上无法稳定控制最大高度、滚动、分组标题、选中颜色和品牌样式，因此长列表会超出合理视区，并出现与 CapaPort 黑／米白／橙色品牌不一致的系统蓝色高亮。

## 目标

1. 按钮高度作为唯一基准，桌面端和 Web 端所有 `Button`、单行 `Input`、`Dropdown`、日期/时间控件和搜索控件共用同一个 `--control-height`。
2. 将两端业务页面中的原生 `select` 迁移为统一的 CapaPort Dropdown。
3. Dropdown 列表最大高度为 320px，超过后仅列表内部滚动。
4. Dropdown 在视口下方空间不足时向上展开，并始终保持在可见区域内。
5. 保持现有黑／米白／橙色品牌，视觉更精致、现代、克制。
6. 保持完整的键盘操作、焦点反馈和语义化无障碍能力。

## 非目标

- `Textarea`、Markdown 编辑器、代码编辑器及其他多行编辑器单独处理，不接入单行控件高度变量，也不强制为 44px。
- 图标按钮单独处理，不接入单行控件高度变量，也不强制为 44px。
- 不把复选框、单选框、开关和文本按钮强制拉伸到标准单行控件高度。
- 不改变现有表单字段含义、接口参数、权限规则或业务校验。
- 不在本次调整中重构页面布局或品牌色体系。

## 统一尺寸体系

桌面端与 Web 端分别在应用根样式中声明同名设计变量：

```css
--control-height: 38px;
```

下列标准控件必须直接读取该变量，不再在页面级样式中单独写 40px、44px 等高度，也不允许通过另一套尺寸变量间接产生不同高度：

- `Button`：标准主按钮、次按钮和危险按钮
- `Input`：单行文本、密码、邮箱、手机号和数字输入框
- `Dropdown` 触发器
- 日期与时间控件：`date`、`time`、`datetime-local` 及项目内封装的单行日期选择器
- 搜索控件：原生 `search` 输入和项目内封装的单行搜索框
- 与输入框同行的操作按钮

上述控件统一使用固定 `height: var(--control-height)` 与一致的 `box-sizing: border-box`。边框、内边距、图标、清除按钮和加载态不得改变外框几何高度。禁用状态只能改变颜色与透明度，不得改变高度、边框占位、内边距或外边距。控件组使用交叉轴拉伸或统一高度，不依靠局部像素补偿。

## Dropdown 组件架构

桌面端与 Web 端各自在现有 UI 组件层提供 `Dropdown`，使用相同的公开接口和交互契约。这样可以复用一致行为，同时允许两端在各自样式入口中使用品牌变量，不引入新的跨应用 React 运行时依赖。

建议接口：

```ts
type DropdownOption = {
  value: string;
  label: ReactNode;
  disabled?: boolean;
};

type DropdownGroup = {
  label: string;
  options: DropdownOption[];
};

type DropdownProps = {
  value?: string;
  options: Array<DropdownOption | DropdownGroup>;
  placeholder?: string;
  disabled?: boolean;
  ariaLabel?: string;
  onValueChange: (value: string) => void;
};
```

组件保持受控：页面负责 `value`，选择后通过 `onValueChange` 返回字符串值。未知值不得导致崩溃；组件显示安全回退文本并允许用户重新选择。禁用选项不可被指针或键盘选中。

## 弹层与滚动

弹层通过 Portal 渲染到 `document.body`，使用触发器的视口坐标计算位置和宽度：

- 默认向下展开。
- 下方不足以容纳合理列表高度且上方空间更多时向上展开。
- 最大高度为 320px，同时受当前视口可用高度约束。
- 超出高度时仅选项区域 `overflow-y: auto`，页面本身不因长列表发生横向或纵向抖动。
- 打开期间在窗口缩放和滚动时重新定位；触发器消失或组件卸载时立即关闭。
- 弹层宽度至少与触发器一致，长文本截断，不撑破页面。

分组标题固定使用弱化的辅助色和紧凑间距，不可选择。普通选项采用米白底；悬停与键盘活动项使用浅橙底；已选项使用品牌橙色文字、勾选标记和克制的强调底色，不使用系统蓝色。

## 交互与无障碍

- 触发器使用 `role="combobox"`、`aria-expanded`、`aria-controls` 和 `aria-activedescendant`。
- 弹层使用 `role="listbox"`，选项使用 `role="option"` 与 `aria-selected`。
- `Enter`、`Space` 打开；上下方向键移动活动项；`Enter` 确认；`Escape` 关闭并将焦点还给触发器。
- 打开后活动项优先定位到当前选中值，否则定位到第一个可用选项。
- 点击外部关闭；点击禁用项不关闭。
- 保留清晰的 `:focus-visible` 橙色焦点环。
- 列表滚动时，键盘活动项必须自动保持在可见区域内。

## 迁移范围

迁移桌面端和 Web 端业务源代码内全部原生 `select`，包括但不限于：组织切换、空间与策略、成员管理、组织设置、安全中心、审计筛选、本地发现、能力创作、能力库和市场页面。同时扫描两端全部单行 `input`、日期/时间控件、搜索控件和标准按钮，移除页面级高度分叉。

原有 `optgroup` 数据改为 `DropdownGroup`。原有 `event.currentTarget.value` 处理改为 `onValueChange(value)`，不改变其后续状态更新和接口参数。

完成后，目标应用业务源码中不再残留可见原生 `select`。若系统级文件选择器等非 Dropdown 控件存在，不在本次迁移范围内。

## 样式收敛

两端删除页面级对标准单行控件的高度覆盖，统一由基础样式负责：

- `Button`、单行 `Input`、`Dropdown`、日期/时间控件和搜索控件全部通过 `--control-height` 获得 38px 高度。
- 相同的边框宽度、圆角、字体行高和左右内边距。
- 输入框、Dropdown 和按钮在同一行时基线与外框完全对齐。
- 禁用状态只改变颜色与透明度，不改变高度、边框占位、内边距或外边距。
- `Textarea`、图标按钮和多行编辑器使用各自的尺寸规则，不强制为 44px。
- 小屏下允许控件组换行，但单个控件仍保持 38px 高度。

## 验证与验收

### 组件测试

- 受控值正确显示和更新。
- 分组标题、禁用项和未知值正确处理。
- 上下方向键、Enter、Space、Escape 和焦点返回正确。
- 点击外部关闭，点击内部与禁用项行为正确。
- 长列表最大高度为 320px，并产生内部滚动。
- 视口底部空间不足时向上展开。

### 布局测试

- 桌面端与 Web 端分别断言 `Button`、单行 `Input`、`Dropdown`、日期/时间控件和搜索控件的计算高度均为 `var(--control-height)` 当前对应的 38px。
- 断言加载态和错误态不会改变控件高度；禁用态只改变颜色与透明度，不改变任何几何尺寸。
- 断言 Dropdown 弹层不会造成页面横向溢出。
- 使用代表性表单验证同行输入框、Dropdown 与按钮上下边缘完全对齐。

### 回归检查

- 对两端源码执行原生 `select` 残留扫描，并扫描标准单行控件是否存在绕过 `--control-height` 的页面级固定高度。
- 运行类型检查、Lint、组件测试、相关端到端测试和生产构建。
- 桌面端重点回归组织设置、空间与策略、审计日志和能力安装流程。
- Web 端重点回归组织管理、安全策略、市场与组织切换流程。

## 验收标准

1. 两端所有 `Button`、单行 `Input`、`Dropdown`、日期/时间控件和搜索控件均由同一个 `--control-height` 驱动，视觉及计算高度一致，当前均为 38px。
2. 两端所有可见原生 Dropdown 均由统一组件承载。
3. 长列表不超过 320px，内部可滚动，不遮挡整个窗口。
4. Dropdown 无系统蓝色样式，符合黑／米白／橙色品牌。
5. 鼠标、键盘和屏幕阅读器操作路径完整。
6. 页面无新增横向溢出、滚动抖动或业务行为回归。
